Operating Systems Programming Assignment 02: a C implementation of `ls`, extended
incrementally from Muhammad Arif Butt's starter program.

**Student:** Ghania Malik - **Roll number:** BSDSF24A038

## Build and run (GNU/Linux)

Requires GCC, GNU Make and libc development headers. Tests additionally need Python 3.

```sh
git clone https://github.com/Ghaniaa-malik/BSDSF24A038-OS-A02.git
cd BSDSF24A038-OS-A02
make
./bin/ls
./bin/ls -l src
./bin/ls -x .
./bin/ls -R src
./bin/ls -lR .
make test
man -l man/ls.1
```

This is Linux/POSIX code. On Windows, use a Linux VM or WSL with the build tools.
The downloadable release asset `ls` is an Ubuntu 24.04 x86-64 ELF executable.
After downloading it, use `chmod +x ls` and run `./ls`. Build from source on other
architectures or older systems with incompatible libc versions.

## Implemented behavior

- `-l`: aligned long format, special permission bits, owner/group names, timestamp,
  total blocks, device numbers and symbolic-link targets.
- Default: terminal-aware columns filled down, then across; 80-column fallback.
- `-x`: columns filled across, then down. The last of `-l` and `-x` wins.
- All modes: alphabetical order using `qsort` and case-sensitive `strcmp`.
- Colors: blue directories, green executables, red .tar/.gz/.zip archives,
  pink/magenta symlinks, and reverse-video special files.
- `-R`: sorted recursive directory traversal with headers, compatible with `-l`
  and `-x`; does not follow symlink directories.
- Multiple operands, file operands, hidden-entry exclusion, diagnostics and
  nonzero exit status on errors. Use `--` before operands beginning with a hyphen.

Colors are emitted even when redirected. Fixed-width columns and byte-based
filename lengths follow the assignment's layout algorithm. This is a subset of
GNU ls: see [REPORT.md](REPORT.md) for design choices and limitations.

## Project layout

```text

VERSION            current version
REPORT.md          answers to all twelve report questions
tests/test_ls.py   Linux filesystem and pseudo-terminal integration tests
.github/workflows/ Linux build, tests and binary artifact
```

The bin, obj and man directories are tracked with placeholders. Build products
are excluded from Git; each GitHub Release contains that version's binary.

## Validation

[Linux CI runs](https://github.com/Ghaniaa-malik/BSDSF24A038-OS-A02/actions) compile
with warnings treated as errors and run the Python integration suite. Each release
links to its passing feature run. Tests check GNU long-format metadata, permission
bits, terminal widths, both column orders, sorting, file-type colors, recursive
paths, symlink loops and errors. The final version also runs under AddressSanitizer
and UndefinedBehaviorSanitizer. The regular optimized binary is uploaded before
the sanitizer rebuild.
